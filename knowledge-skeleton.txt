# LinkedKnowledge 项目知识图谱 (细化版)

## 1. 工程与环境 (Infrastructure)
### 1.1 启动与配置
- [ ] **启动脚本分析**: 阅读 `start.sh` / `Dockerfile`，理解项目如何启动。
- [ ] **配置文件**: 弄懂 `application.yml` 里的端口、数据库地址、文件路径配置。
- [ ] **依赖管理**: 查看 `pom.xml`，识别核心依赖（Spring Boot, MyBatis, Lombok等）。

### 1.2 数据库设计 (Database Schema)
- [ ] **ER图理解**: 画出用户、笔记、标签、知识节点之间的关系。
- [ ] **表结构**: 逐字段理解 `note`, `user`, `link` 表的设计意图。
- [ ] **索引与性能**: 分析哪些字段建了索引，为什么？

## 2. 核心业务链路 (Business Logic)
### 2.1 用户与认证 (User & Auth)
- [ ] **注册流程**: 从 Controller 接收参数 -> Service 校验 -> Mapper 入库。
- [ ] **登录/JWT**: 密码加密验证、Token 生成、拦截器校验 Token。
- [ ] **权限控制**: 用户只能操作自己的笔记（UserId 透传与校验）。

### 2.2 知识节点 (Knowledge Node)
- [ ] **CRUD 接口**: 节点的增删改查接口逻辑。
- [ ] **富文本内容**: 如何处理长文本/Markdown 内容的存储与回显。
- [ ] **父子节点**: 如何实现节点的层级关系（ParentId 设计）。

### 2.3 关联关系 (Linking & Graph)
- [ ] **双向链接**: 如何实现 `[[节点名]]` 这种语法解析与跳转。
- [ ] **引用计数**: 当一个节点被引用时，如何更新引用数。
- [ ] **图谱构建**: 如何从数据库数据生成用于展示的 Graph JSON 数据。

## 3. 接口与交互 (API & Interaction)
### 3.1 RESTful 设计
- [ ] **URL 规范**: 检查项目的 URL 是否符合 Rest 风格。
- [ ] **统一响应**: 分析 `Result.java` 或统一包装类的设计。
- [ ] **异常处理**: 全局异常捕获（`@ControllerAdvice`）如何返回错误信息。

### 3.2 数据校验
- [ ] **参数校验**: 使用 `@Valid` 或手动校验入参。
- [ ] **业务校验**: 比如“不能自己链接自己”、“不能删除有子节点的父节点”。

## 4. 高阶与优化 (Advanced)
### 4.1 搜索功能
- [ ] **模糊查询**: SQL 层面的 `LIKE` 查询。
- [ ] **全文检索**: 是否引入了 Elasticsearch/Lucene（如果没有，思考如何加）。
### 4.2 缓存策略
- [ ] **热点数据**: 首页/热门节点是否使用了 Redis 缓存。
- [ ] **缓存一致性**: 数据更新时，如何清理缓存。

## 5. 学习复盘 (Meta-Learning)
### 5.1 错误类型库
- [ ] **NullPointerException**: 对象未判空。
- [ ] **SQLSyntaxError**: SQL 语句写错/表名错。
- [ ] **404 Not Found**: 路径映射错误/包扫描遗漏。
- [ ] **500 Server Error**: 业务逻辑异常/数据库死锁。
